    What is a hash?

    A hash function turns any input into a fixed-length fingerprint. The same input always gives the same hash, and changing a single character gives a completely different one. Hashes are used to check that files and messages have not changed, to compare data without revealing it and in digital signatures.

    Which algorithm should I use?

    Use SHA-256 or stronger for new work. SHA-1 is shown for checking older systems but is no longer considered secure against deliberate collisions. For storing passwords, use a slow password hashing function such as Argon2, bcrypt or scrypt rather than a plain SHA hash.

    Verify a download with its checksum

    Software sites often publish an MD5 or SHA-256 checksum next to a download. Choose the downloaded file, paste the published checksum into Compare with an expected hash, and the tool tells you whether they match. A match means the file arrived complete and unchanged. The file is read by your browser and never uploaded, so this works for large installers and private documents alike.

    Frequently asked questions

    How do I check the MD5 or SHA-256 of a file?

    Choose the file under ‘Or choose a file’. Its MD5, SHA-1, SHA-256, SHA-384 and SHA-512 hashes appear straight away. Paste the expected value to see if it matches.

    Can a SHA-256 hash be reversed?

    No. Hashes are one-way. The only way to find the input is to guess it and compare hashes, which is why short or common inputs are weak.

    Why does my hash differ from another tool?

    Hashes are calculated on the exact bytes. Extra spaces, line breaks or a different text encoding change the result. This tool hashes UTF-8 text.

    Is my text sent anywhere?

    No. Hashing uses the Web Crypto API in your browser.
